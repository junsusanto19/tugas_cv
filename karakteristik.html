Karakteristik

 

Bagian ini membahas aspek teknis MNIST secara mendalam: struktur data, ukuran dan tipe citra, format penyimpanan asli, preprocess yang diterapkan saat pembentukan dataset, statistik kelas dan distribusi, serta implikasi teknis ketika digunakan dalam eksperimen machine learning. Pernyataan teknis inti tentang MNIST (jumlah sampel, ukuran 28×28, dan pembentukan train/test) dapat diverifikasi pada sumber resmi MNIST.

 

Ringkasan angka-angka kunci

  • Total sampel: 70.000 citra (60.000 training, 10.000 test).
  • Resolusi: 28 × 28 piksel (grayscale), rentang intensitas 0–255 pada file biner; sering dinormalisasi ke [0,1] atau [-1,1].
  • Kelas: 10 kelas — digit 0 sampai 9 (discrete labels: 0..9).
  • Format penyimpanan asli: format IDX (binary IDX3/IDX1 untuk gambar dan label). Banyak library menyediakan loader built-in.
  • Preprocessing historis: size-normalization ke 20×20 kemudian ditempatkan ke 28×28, anti-aliasing (grayscale) dan translasi agar pusat massa piksel berada di tengah.

 

Format file & cara memuat (IDX)

Format asli MNIST disimpan sebagai empat file IDX sederhana: train-images-idx3-ubyte, train-labels-idx1-ubyte, t10k-images-idx3-ubyte, dan t10k-labels-idx1-ubyte. IDX adalah format biner ringkas yang merekam metadata (tipe, dimensi) lalu data raw. Kelebihan format ini: hemat ruang, mudah diparsing; kekurangannya: bukan format gambar standar (PNG/JPEG), sehingga kadang perlu konversi bila Anda ingin menampilkan contoh citra atau menyimpan ulang. Informasi implementasi loader IDX banyak tersedia di perpustakaan (mis. torchvision.datasets.MNIST, tensorflow.keras.datasets.mnist) dan juga pada halaman resmi MNIST. :contentReference[oaicite:2]{index=2}

3.3 Detil preprocess saat pembentukan dataset

Langkah-langkah preprocessing historis yang paling sering dikutip adalah:
  1. Size normalization: setiap karakter diperkecil/diubah skala agar muat dalam kotak 20×20 piksel sembari mempertahankan rasio aspek.
  2. Anti-aliasing / grayscaling: hasil downsampling menghasilkan nilai intensitas grey (bukan hanya binary), sehingga citra memiliki nuansa abu-abu yang merepresentasikan tepi halus.
  3. Centering: gambar ditempatkan pada kanvas 28×28 dengan menerjemahkan posisi sehingga pusat massa (center of mass) dari piksel berada di tengah frame. Ini memastikan posisi relatif digit konsisten antar sampel. :contentReference[oaicite:3]{index=3}

 

Statistik kelas & distribusi

MNIST memiliki 10 kelas yang secara konseptual seimbang pada tingkat nominal (setiap kelas hadir dalam jumlah besar). Namun secara teknis, distribusi frekuensi tiap digit tidak sepenuhnya identik — beberapa digit (mis. '1' atau '0') cenderung muncul sedikit lebih sering tergantung kumpulan asli yang diambil dari NIST. Ketidakseimbangan tersebut biasanya kecil dan tidak mengganggu pelatihan model dasar, tetapi saat melakukan analisis kesalahan (error analysis) atau eksperimen few-shot, penting untuk memeriksa frekuensi per-kelas. Tools modern (pandas, matplotlib) bisa dipakai untuk menghitung dan mem-visualisasi histogram label untuk memastikan apakah samplenya seimbang untuk eksperimen tertentu.

 

Representasi numerik & normalisasi untuk training

Praktik yang umum diterapkan sebelum melewatkan citra ke model adalah:
  • Konversi tipe: dari uint8 (0–255) ke float32.
  • Skala: membagi dengan 255 untuk mendapatkan rentang [0,1] atau melakukan normalisasi z-score berdasarkan mean/std dataset.
  • Augmentasi ringan (opsional): rotasi kecil, translasi, noise Gaussian, shear — berguna untuk mengevaluasi robustness. Perlu diingat augmentasi yang berlebihan bisa mengubah sifat tugas (mis. 180° rotasi membuat 6 menjadi 9 dll.).

 

Implikasi teknis untuk arsitektur & eksperimen

Karena ukuran citra yang kecil (28×28), MNIST memungkinkan eksperimen sangat cepat dan penggunaan arsitektur ringan:
  • Parameter kecil: model sederhana (MLP dengan 1–2 hidden layer atau CNN kecil seperti LeNet-5) sudah mencapai akurasi tinggi, sehingga riset perlu hati-hati: perbaikan kecil di MNIST belum tentu bermakna di dataset lain.
  • Batch size & throughput: dimensi kecil memperbolehkan batch besar sehingga konvergensi cepat; namun benchmarking harus mempertimbangkan throughput (images/sec) bila membandingkan perangkat keras.
  • Precision & storage: karena input kecil, Anda bisa menyimpan dataset dalam berbagai format (IDX, Numpy .npy, HDF5) tergantung kebutuhan eksperimen (kecepatan I/O vs portabilitas).

 

Contoh: konversi dan melihat sample (Python, tanpa library besar)

  import urllib.request, gzip, numpy as np
  def load_images(url):
      with gzip.open(urllib.request.urlopen(url)) as f:
          data = f.read()
      # skip 16-byte header, parse uint8
      images = np.frombuffer(data, dtype=np.uint8, offset=16)
      images = images.reshape(-1, 28, 28)
      return images
  imgs = load_images('http://yann.lecun.com/exdb/mnist/train-images-idx3-ubyte.gz')
  print(imgs.shape)  # (60000, 28, 28)
